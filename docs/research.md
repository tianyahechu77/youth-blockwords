## 一、技术路线：怎么把中文送进 Android 输入框

### 试过但不可行的方案

| 方案 | 结果 | 原因 |
|---|---|---|
| `adb shell input text "中文"` | ❌ | 只支持 ASCII。这是 Android 的限制，不是 App 的 |
| `service call clipboard` 写剪贴板 | ❌ | Android 16 上直接报 `Parcel` 错误（`Allocation ... above allowed limit`），接口签名已变；读回是 `No items` |
| 安装 ADBKeyboard 输入法（广播直送中文） | ⚠️ | 方案本身可靠，但小米/Redmi 上被 `INSTALL_FAILED_USER_RESTRICTED` 拦住。需开发者选项里额外的「USB 安装」开关 |
| 点输入法面板上的剪贴板候选词 | ❌ | 那块面板**不在 Android UI 树里**，`uiautomator dump` 抓不到，坐标只能靠截图猜。实测多次坐标都对不上 |

### 最终可用方案

```
电脑 Set-Clipboard 写 Windows 剪贴板
   ↓  输入法跨设备同步（微信输入法实测可用）
手机剪贴板
   ↓  adb shell input keyevent 279（粘贴键）
App 输入框
```

每一步的坑：

1. **PowerShell 调 adb 必须设 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`**
   不设的话 PowerShell 按 GBK 解码 UTF-8 输出，`添加关键词` 变乱码，脚本永远找不到按钮。
   这个 bug 导致最初连续失败三次，且报错信息完全看不出来。

2. **PowerShell 脚本文件保存为 UTF-8 with BOM**
   PS 5.1 没有 BOM 会按系统代码页读，中文直接错。

3. **`keyevent 279` 是粘贴键**，不是 `input text`。前提是手机上当前输入法有剪贴板内容。

4. **剪贴板同步有延迟**，实测 2.5 秒会偶尔拿到上一个词。脚本采用「粘贴后立刻给下一个词预置剪贴板」的流水线，把同步时间藏进提交等待里。

### 坐标

- 屏幕：物理 1440×3200，渲染 1080×2400（`wm size` 的 Override size）
- 触摸设备 `goodix_ts` 的 `ABS_MT_POSITION_X` 最大 143999、`Y` 最大 319999
- **换算：`raw ÷ 100 = 物理像素`，再 `× 0.75 = 逻辑坐标`**

标定值（1080×2400，键盘收起/弹出两态不同）：

| 控件 | 键盘收起 | 键盘弹出 |
|---|---|---|
| 添加关键词 | (575, 2319) | 同左（列表页固定） |
| 输入框 | (492, 1696) | (493, 957) |
| 提交 | (539, 2191) | (539, 1412) |

换机型请先用 `fill.ps1 -Calibrate` 重新读一遍。

### 小米/Redmi 的额外开关

`设置 → 更多设置 → 开发者选项 → USB 调试（安全设置）`

不开的话所有注入（`tap`、`keyevent`、`text`）都会被拒：

```
Injecting input events requires the INJECT_EVENTS permission
```

注意：`dumpsys package com.android.shell` 里 `INJECT_EVENTS: granted=true` 也可能仍然被拒——权限是给了，但厂商开关在更底层拦。**改完开关必须重新插拔数据线。**

### 判断命令是否成功的教训

早期用 `adb shell input keyevent 279 2>&1 | head -3` 判断成败，`head` 把真正的报错截掉了，连续误判「注入已恢复」。
**判断 adb 命令成败时，要么看完整输出，要么 grep 关键字，不要截断。**

## 二、词从哪来

刻意避开了「从开源词库批量导入」这条路，原因见下。

### 一手来源

| 来源 | 时间 | 提供了什么 |
|---|---|---|
| 抖音黑板报《关于持续治理涉未成年人不良内容的公告》 | 2026-10 | 四类典型违规情形：隔空猥亵、篡改经典动画、冒用未成年身份擦边、宣扬抽烟喝酒 |
| 央视网《这些「加密术语」，可能伤害我们的孩子！》 | 2026-01 | `梦回大唐`（窒息游戏）、`ED妹`（进食障碍）、`梦角哥`/`MJG`（虚拟角色恋爱） |
| 央视《法治在线》暗黑动漫调查 | 2026-04 | `喰种`、`食尸鬼`、`东京吃货` 等谐音马甲；实测正片下架后这些词仍可搜到 |
| 中国网络社会组织联合会 × 抖音《未成年人新型网络风险防护指南》 | 2026-08 | 五类隐蔽风险：以交友招募为名、教学壳低俗芯、正常外壳异常内容、圈层暗语、危险挑战 |
| 央视网《致幻「OD圈」危害青少年》 | 2024-06 | `OD`、`小美`（右美沙芬）、`多多`（曲马多）、`思诺思` |

### 现成开源词库的评估

| 项目 | 规模 | 许可 | 判断 |
|---|---|---|---|
| [houbb/sensitive-word](https://github.com/houbb/sensitive-word) | 6 万词，DFA，带分类标签 | Apache-2.0 | 工程上最成熟（14 万 QPS），但面向 UGC 通用审核，**不区分年龄段** |
| [fwwdn/sensitive-stop-words](https://github.com/fwwdn/sensitive-stop-words) | 分类 txt：色情 304 / 涉枪涉爆 430 / 政治 325 / 网址 1.45 万 | Apache-2.0 | 唯一格式上能直接用的 |
| [RunEnd/Sensitive-lexicon](https://github.com/RunEnd/Sensitive-lexicon) | 17 文件约 1.2 MB，十万条量级 | — | 政治类占大头，与青少年场景无关 |

### 关键结论：来源不是瓶颈

把色情类 304 词按抖音规则过滤一遍：

```
原始词条        304
纯中文          289
≤ 5 汉字         289   ← 一条都没被长度规则淘汰
```

也就是说，**规则几乎不淘汰任何词**。真正的约束是：

1. 手机上的名额只有几十个
2. 大部分通用敏感词不会出现在短视频标题里（擦边内容用的是隐晦词，不是直白词）

所以导入 6 万词，能填进去的还是那几十个。**这活儿的关键是筛选，不是搜集。** 本仓库因此只做精选。

## 三、优先级是怎么定的

名额有限，就必须回答「同样占一个位置，谁更该拦」。

排序逻辑：

1. **有生命危险的**（`梦回大唐`、`死亡三秒`、`窒息挑战`、`蓝鲸`、`约死群`、`烧炭`）
2. **造成不可逆身体伤害的**（`催吐`、`养兔子`、`极端节食`、`右美沙芬`、`思诺思`、`曲马多`）
3. **针对未成年人的诱骗入口**（`私影`、`童星招募`、`私密照`、`捐卵`、`代孕`）
4. **色情与低俗引流**（`福利姬`、`懂的都懂`、`私我`、`看我主页`）
5. **校园伤害**（`校园暴力`、`霸凌`、`约架`）
6. **观点与情绪类**（迷信、性别对立、部分情绪词）—— 排在最后，甚至不建议加

一句话：**`迷信` 拦的是观点，`窒息挑战` 拦的是人命，同样占一个名额，优先级不该一样。**

### 唯一一组被标为「不建议屏蔽」的

情绪类（`抑郁`、`想死`、`轻生`、`活不下去`）。

原因是双重的：

- 屏蔽后孩子真的痛苦时**搜不到任何求助内容**
- 同时你失去了**最早的预警信号**

原则是：**屏蔽方法词（`烧炭`、`跳桥`、`割腕`），保留情绪词。**

## 四、已知的局限

- **不识别画面**。这是整个词库路线的天花板
- 拼音缩写、拆字、表情替代不识别（平台官方说明明确说了）
- 暗语生命周期短。`梦回大唐` 被曝光后会被换掉，这份词库需要持续更新
- 只在 Android 上验证过。iOS 无对等方案

如果要做画面层面的防护，只能靠平台青少年模式，或设备级的家长控制软件。
